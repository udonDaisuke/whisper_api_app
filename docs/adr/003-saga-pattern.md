# ADR-003: 後処理パイプラインへの Saga パターン採用

> ステータス: Accepted
> 日付: 2026-03-26
> 決定者: udonDaisuke

## 背景

Phase 4-5 の後処理 (話者分離 → 感情認識 → トピック検出 → TTS) は処理時間が長く、途中でクラッシュする可能性がある。各ステップで中間結果の保存・失敗時のクリーンアップが必要。

## 決定

後処理フローを `PostProcessingSaga` として実装する。
各ステップは前進トランザクションと補償トランザクション (失敗時のロールバック) を持つ。

## 理由

- **耐障害性**: 途中クラッシュ後に中断ポイントから再開できる
- **可観測性**: 各ステップの状態 (pending / running / done / failed) を JobRepository で追跡できる
- **独立性**: ステップ間の依存を明示的に管理でき、並列化・スキップも容易

## 実装の単純化 (Stage 1)

Stage 1 では補償トランザクションは「中間ファイルの削除」のみ。
Redis/Celery なしの同期実行だが、インタフェースは Stage 2 のキュー対応を先読みした設計にする。

## 撤回条件

後処理が 1 ステップのみに留まる場合。シンプルな関数呼び出しで十分。
