# ADR-002: Plugin Registry パターンの採用

> ステータス: Accepted
> 日付: 2026-03-26
> 決定者: udonDaisuke

## 背景

Phase 4-5 で話者分離・感情認識・TTS など複数の AI モデルが追加される。これらをサービス層にハードコードすると、モデル追加のたびに既存コードへの変更が必要になる。

## 決定

`PluginRegistry` と `ModelPlugin` インタフェース (Python Protocol) を導入する。
新モデルは `ModelPlugin` を実装し Registry に登録するだけでシステムに組み込める。

## 理由

- **拡張開放・修正閉鎖 (OCP)**: 新モデル追加に既存コード変更不要
- **テスト容易性**: Mock プラグインを Registry に登録するだけで単体テスト可能
- **A/B テスト**: 同一 capability の複数プラグインを登録してモデル比較が容易

## トレードオフ

間接層が増えるため、単純なケースでは過剰設計に見える場合がある。
Phase 1 では FasterWhisperPlugin のみだが、Phase 4-5 で価値が発揮される先行投資として許容する。

## 撤回条件

モデル数が 2 種以下に留まり、今後も増えない見通しになった場合。
