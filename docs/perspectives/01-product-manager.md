# プロダクトマネージャー視点の分析

## 1. プロダクトビジョン

**MemoRec（メモレック）**は、「録音するだけで、会議・会話・インタビューのすべてが構造化された記録になる」音声インテリジェンスプラットフォームである。

### 誰のためのプロダクトか

| ペルソナ | 課題 |
|---|---|
| ビジネスパーソン（会議が多い人） | 会議の議事録作成に毎回30分かかる。重要な発言を見落とす |
| UXリサーチャー / ジャーナリスト | インタビュー録音を後から聞き直すのに録音時間と同等の時間がかかる |
| コールセンターQA担当 | 通話品質の評価に感情・トーンの客観的指標がない |
| ポッドキャスター / コンテンツクリエイター | 声の変換・編集に専門ツールが必要で敷居が高い |
| 個人の学習者（講義メモ） | 講義を聞きながらメモを取ると集中できない |

### 提供する価値

1. **記録の自動化** -- 録音ボタンを押すだけで、文字起こし・話者識別・トピック分類・感情ラベルが自動付与される
2. **検索可能な音声アーカイブ** -- 「あのとき誰が何を言ったか」をテキスト検索・タグ・トピックから即座に見つけられる
3. **音声の再利用** -- メタデータ付きの音声をVoice Conversionで別の声に変換し、プライバシー保護やコンテンツ制作に活用できる

## 2. ユーザーストーリー

| # | ストーリー | 関連機能 |
|---|---|---|
| US-1 | 会議参加者として、会議を録音開始し、リアルタイムに文字起こしが画面に表示されるのを見たい | リアルタイム文字起こし |
| US-2 | チームリーダーとして、過去の会議録音を一覧で見て、タイトル・日時・タグで検索したい | 録音管理・検索・タグ |
| US-3 | UXリサーチャーとして、インタビュー録音に後からタグを付けたい | タグ付け |
| US-4 | プロジェクトマネージャーとして、会議中に話題が切り替わったタイミングとトピック名を自動で取得したい | トピック検出 |
| US-5 | 議事録の読者として、「誰が」発言したかが明記された文字起こしを読みたい | 話者分離 |
| US-6 | コールセンターQA担当として、通話中の顧客の感情変化をタイムライン上で確認したい | 感情分析 |
| US-7 | ポッドキャスターとして、録音した音声を別のキャラクターの声に変換して配信したい | Voice Conversion |
| US-8 | 個人ユーザーとして、スマートフォンのブラウザからも録音・文字起こしを使いたい | モバイル対応 |

## 3. MVP定義

「文字起こし + 永続化 + 検索」が正しく動き、ユーザーが繰り返し使う理由がある状態。

**含めるもの:**
- リアルタイム文字起こしUI
- 録音セッションの保存と一覧表示（DB永続化）
- 録音への手動タグ付け・編集
- Whisperモデルのアップグレード（tiny → large-v3）
- ユーザー認証

**含めないもの（Phase 2以降）:**
- トピック自動検出、話者分離、感情分析、Voice Conversion

## 4. ロードマップ

- **Phase 1 (Foundation)**: 録音・文字起こし・DB永続化・タグ・検索・認証 — 2-3ヶ月
- **Phase 2 (Intelligence)**: トピック検出・話者分離・自動タグ・要約 — 2-3ヶ月
- **Phase 3 (Emotion)**: 感情分析・感情タイムライン・ダッシュボード — 2-3ヶ月
- **Phase 4 (Voice)**: Voice Conversion・キャラクター管理・メタデータ保持変換 — 3-4ヶ月

## 5. 競合との差別化

1. **プライバシーファースト** -- ローカル実行 & セルフホスト。音声データが一切外部に出ない
2. **感情分析 + Voice Conversion** -- 他にないレイヤーの音声インテリジェンス
3. **オールインワン・パイプライン** -- 文字起こし→話者分離→トピック→感情→VCを一つで完結
4. **開発者フレンドリー** -- APIファーストアーキテクチャ
